Rebuild it

  
One suggestion, step by step

  
Each step depends on the one before it. Click the steps in the order the program runs them for one flagged case in a live run, first to last.

  

    

    

    

    

  

  
Why this order?The prompt and its cache key come first, then the cache is checked, because a saved valid reply means no model call is needed. The gateway wraps the call so that the counter sits inside the retry, and the timer wraps both. The trace is recorded in a finally after the timer has closed, so the latency is already filled in. The reply is checked only after the call is done, a repair goes through the same gateway, and only a valid reply is saved, with a safe write.

Retry, give up, repair or mark invalid?

  

  
Match the response to the problemWaiting fixes a busy service, not a missing key or a wrong value. A reply that cannot be read gets one repair. A reply with wrong values is never repaired, because asking again only invites a better-sounding invention.

Decorators and context managers

  

  

    
You wantRemember

    
A decoratorA function that takes a function and returns a new one. @name above def means f = name(f)

    
Keep the name and docstring@functools.wraps(function) above def wrapper

    
A decorator with settingsThree layers: settings, then the function, then each call. Brackets are required: @retry_transient(...)

    
Stacking orderThe decorator nearest def wraps first. A counter inside a retry counts attempts. Outside, it counts calls

    
A context manager__enter__ and __exit__, or @contextmanager with one yield and a try/finally

    
A closureA function plus the outside variables it uses. nonlocal lets it change one
